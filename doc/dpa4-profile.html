DPA4 Profile Paths

两条 profile 路径各自使用不同输入：直接调用 DPA4Model 做单卡推理，或用 LAMMPS 运行单 rank/多卡 MPI 模拟。生成的 NPZ 仅供直接推理，不是 LAMMPS data 文件。

两条路径 输入与产物 TileLang 后续测试

01 / Execution

选择运行路径

Direct · one HCU

独立测试 DPA4Model

NPZ / geometry → DPA4Model.eval → torch.profiler

不启动 LAMMPS。输入是 NPZ（coords、atom_types、cells）或当前几何读取器支持的正交盒几何；模型由 DeepMD 加载。可用 generate-data 从真实周期结构扩胞后生成可复用 NPZ。

python tests/deepmd/test_dpa4_inference_profile.py dpa4 \
  --model-file /models/water.pt \
  --input-npz /systems/water.npz \
  --device cuda:0 --max-atoms 8192 \
  --tilelang-ops "" \
  --output-dir /tmp/profile-baseline

--tilelang-ops "" 显式关闭 TileLang selectors，作为 baseline。输出包含 Chrome trace 和 JSON summary；--max-atoms 是上限，需检查 summary 的实际 atom_count。

LAMMPS · one rank per HCU

使用 LAMMPS 模拟

LAMMPS data + input template + .pt2 → lmp / MPI

此路径传入原生 LAMMPS data 文件和模板。--gpu-ids 中每个 ID 对应一个单机 rank；多个 ID 需 MPI 和 with-comm 模型。仓库模板 tests/deepmd/dpa4_water_profile.template 对应水样例 O,H 类型顺序。

python tests/deepmd/test_dpa4_inference_profile.py lammps \
  --model-file /models/water-with-comm.pt2 \
  --data-file /path/to/lammps/examples/rdf-adf/data.spce \
  --lammps-input tests/deepmd/dpa4_water_profile.template \
  --lammps-exe /opt/dtk/bin/lmp --mpi-exe mpirun \
  --gpu-ids 0,1,2 --replicate 2,2,2 --steps 0 \
  --output-dir /tmp/profile-lammps

3 个 GPU ID 会启动 3 个 MPI rank；2,2,2 将 4,500 原子的样例扩为 36,000 原子。默认 --steps 0；增加 steps 时模板还会计算 SPC/E bond/angle 项。该样例 data 是 full-style LAMMPS 输入，应通过 --data-file 使用，不要当作直接路径的 --geometry。

02 / Contract

输入和输出不能混用

路径必需输入扩胞方式profile 产物
直接 dpa4eager DeepMD model + NPZ/支持的 geometryprofile 根据可用显存估算；generate-data 可离线扩 NPZ单次 eval 的 Chrome trace + JSON summary
lammpsfrozen .pt2 + LAMMPS data + template + lmp；多卡另需 MPI模板内 replicate ${rx} ${ry} ${rz}DeepMD DP_PROFILER trace、rank logs、JSON summary

直接推理的 generate-data 输出是 NPZ，不是 LAMMPS read_data 文件。多卡 LAMMPS 运行要求单机每 rank 一个可见 GPU 和包含 with-comm 路径的模型；水样例要求 model type map 为 O,H。

03 / TileLang validation

算子接入后，先验正确性，再测性能

不要只比较 profile 时间。保持输入、模型类型映射、实际 atom_count、设备和运行条件一致，并分开验证算子与完整模型。

单算子 parity。 对新 TileLang 算子跑相应单元测试，比较 TileLang 与 PyTorch/reference 的输出误差；一次先启用一个 op，便于定位错误。

完整 DPA4 correctness。 对相同 NPZ 和 eager pt_expt 模型，分别用 tilelang_ops=() baseline 和 tilelang_ops=("radial_basis", ...) candidate，比较 energy、force、virial；先运行现有 DPA4 模型集成测试。

直接 profile 对照。 用相同 --input-npz、--max-atoms、设备和内存参数各运行一次。检查 summary 的 atom_count 与 tilelang_ops；再比较 Chrome trace 的 TileLang kernel/device time、总 wall time 和显存。多次运行并记录中位数，避免把 JIT 首次调用当作稳态结果。

LAMMPS 集成验证（可选）。 .pt2/.pte 的 TileLang selectors 在导出时固定，不能在当前 LAMMPS 命令加载后切换。分别导出 baseline 与已集成 TileLang 的模型，再用完全相同的 data、template、replication、rank 数和 steps 做模拟对照；多 rank 模型需带 with-comm artifact。

TileLang direct dispatch 需要 eager pt_expt checkpoint；普通 pt 不会静默回退，导出的 .pt2/.pte 也不能通过 --tilelang-ops 改变算子选择。
